# The repository becomes a monorepo: four blocks, one pipeline, and a contract that refuses to break

Date: 2026-09-08
Status: Draft, awaiting the operator's review; one adversarial review closed, its findings and their
exits recorded in block 1's pull request
Branch of block 1: `chore/monorepo-move`
ADRs: `docs/adr/0024-three-projects-share-one-repository.md` (block 1, delivered with this
document); one further ADR for the pipeline's SDK, delivered with block 2 (question T)

## 1. Goal

Turn a repository that holds the API server alone into one that holds three projects, and repair
the two defects the move exposes: continuous integration enumerates checks instead of projects, and
the environment the gate needs is a manual setup step rather than a pinned artefact.

This lot builds no client. It leaves the repository able to receive them: two ecosystem roots, a
contract that is an interface rather than documentation, one pipeline that runs the same way on a
workstation and on a runner, and a guard that refuses a breaking change nobody declared.

Every design choice below derives from a question put to the operator during Discuss, one at a
time. Section 3 is that record.

## 2. What exists today

Twelve Gradle modules at the repository root, `docs/openapi.json` generated by the build and
rewritten by the `pre-commit` hook, a `gate` task that aggregates every module's `check` and
`koverVerify` plus two repository-wide checks, and a `validate.yml` that reproduces the gate's parts
rather than calling it.

Five properties of the current state carry the design. Each was read, none assumed.

```
$ grep -c "CI reproduces the gate's parts" .github/workflows/validate.yml
1
$ grep -ho "<ID>[^<]*</ID>" config/detekt/baseline*.xml | sed 's|</ID>||' | grep -c "/"
2
$ grep -n "gradlew" .github/workflows/validate.yml
29:        run: ./gradlew detekt
33:        run: ./gradlew checkNoLongDashes
35:        run: ./gradlew checkEvidenceGuard
55:        run: ./gradlew test koverVerify
76:        run: ./gradlew :api-application:quarkusBuild
$ grep -o '"version"[^,]*' docs/openapi.json | head -1
"version" : "1.0.0-SNAPSHOT"
```

1. **The divergence is documented in the file that causes it.** `validate.yml` says a check added
   to `gate` alone runs on no pull request.
2. **The detekt baselines survive a move.** Two identifiers out of every baseline contain a slash,
   and both are the same `@Path("/{pinId}/image")` inside a signature, not a directory component.
   Relocating a module does not invalidate its baseline. This removes the largest suspected risk of
   block 1.
3. **Two checks in `build.gradle.kts` are repository-wide, and they locate themselves by two
   different mechanisms.** `checkEvidenceGuard` sets `workingDir = rootDir` (line 226).
   `checkNoLongDashes` sets no working directory at all: it runs `git ls-files -z -- .` through
   `providers.exec` and then reads each returned path with `rootDir.resolve(path)` (lines 181 to
   198). Both cover the repository today only because Gradle's root and the repository's root are
   the same directory. Section 4.2 states what each one needs.
4. **The divergence is not hypothetical, and it is live right now.** `check` depends on
   `detektMain` and `detektTest`, which carry detekt's type resolution rules
   (`build.gradle.kts:120`). The commands above are every `gradlew` invocation in `validate.yml`,
   and none of them is `check`. The type resolution rules therefore run on no pull request today,
   and have been caught by the local gate alone.
5. **`info.version` is derived from the Gradle version.** `docs/openapi.json` carries
   `1.0.0-SNAPSHOT`, which is `allprojects { version = "1.0.0-SNAPSHOT" }` (`build.gradle.kts:14`).
   Nothing in `application.properties` or `OpenApiApplication.kt` sets `info-version`. Block 4 has
   to separate them, and the separation is work, not a state to preserve.

## 4. Design

### 4.1 The tree

```
AGENTS.md   README.md   SECURITY.md
agents/     docs/       scripts/    security/    .claude/    .github/   .githooks/
contract/
  openapi.json                     generated, committed, never hand edited
  frozen/                          one document per still served major; empty during the alpha
api/
  AGENTS.md            settings.gradle.kts   build.gradle.kts   Dockerfile   config/   .idea/
  gradlew  gradle/     api-domain/ ... api-application/        the twelve modules, unchanged
clients/                                     built by a later lot
  AGENTS.md            <workspace manifest>
  apps/webapp/         apps/extension/
  packages/api-client/ packages/auth/
.dagger/                                     the pipeline module, block 2
```

The repository root holds no `package.json` and no `settings.gradle.kts`. `scripts/`, `security/`
and `.claude/` stay at the root: the first two serve the repository, and the third is where the
agent instructions and the evidence guard live. `.dagger/` carries its own manifest for its
TypeScript SDK (question T); that file is the Dagger module's own, it is not a workspace root, and
`clients/`'s package manager does not see it. `clients/`'s workspace manifest is written by the lot
that builds `clients/`, which is also the lot that picks its package manager.

#### 4.2.1 The observable for `checkNoLongDashes`

Two plausible implementations of this fix are green and wrong. Leaving the task alone narrows it to
`api/`. Moving only the exec's working directory makes `rootDir.resolve(path)` point at files that
do not exist, `!file.isFile` skips every one of them, and the task passes over nothing. The files
the rule exists for, the prose Markdown at the root and under `agents/` and `docs/`, are exactly
those that end up outside `api/`.

The criterion therefore names an offender, not a green run: put an em dash in `README.md`, run the
gate, and the failure must name `README.md`. Revert, and the gate must pass.

#### 4.2.2 One adjacent defect, tier 1

`README.md` states that `pre-push` runs `./gradlew check koverVerify`. The hook's last line is
`exec ./gradlew gate`. The prose is stale and the hook is right. Corrected in this block, which is
touching the file anyway, and named in its pull request.

### 4.3 The contract and its version

`contract/openapi.json` is the same document `docs/openapi.json` is today, in its proper place. It
keeps the generated regime `agents/writing.md` gives it: rewritten by the build, checked, never
edited by hand.

`contract/frozen/` is created empty in block 1, with its rule written in `AGENTS.md`: a document
enters when a major becomes still served, and leaves when it stops being served. During the alpha
the directory stays empty, because breaking is the stated policy of the README. Populating it is a
`Before beta` event in the backlog.

**Separating the two versions is block 4's work, not a state to preserve.** Section 2, property 5,
records that `info.version` is `1.0.0-SNAPSHOT` because the Gradle version is. Block 4 sets
`quarkus.smallrye-openapi.info-version` explicitly and adds a test asserting that the contract
version **differs** from `quarkus.application.version`. A test asserting only that the field has a
value passes today, against a document where the two are the same string, which is the trap this
paragraph exists to avoid.

### 4.4 The pipeline (blocks 2 and 3)

One Dagger module at `.dagger/`, exposing functions the operator calls by name. The perimeter is
ADR 0024 decision 5: what has a meaning locally.

| Function | Input | What it does |
|---|---|---|
| `gate` | The source directory | Runs the API gate and, once `clients/` exists, the clients gate, with the contract passed from the first to the second |
| `api-gate` | The source directory | The Gradle gate, in a container pinning the JDK 25 toolchain, libvips and `python3` |
| `contract` | The source directory | Produces `contract/openapi.json` and returns it as a directory, so a caller can compare or export it |
| `image` | The source directory | Builds the runtime image, multi architecture |
| `smoke` | The image | Starts the container and waits for `/q/health`, the check `validate.yml` performs today and no workstation can |
| `prose` | The source directory | `checkNoLongDashes` and the evidence guard's tests, which leave Gradle here because their scope is the repository |

The edge between the two ecosystems is an argument, not a convention: the clients function takes
the directory the contract function returned. No path filter and no manifest expresses it, and
nothing can forget to declare it.

**Block 2 opens with a spike, before any workflow file is touched**: run `api-gate` end to end and
show it green. Section 8 says why this is the claim the lot rests on.

**Moving `prose` out of Gradle deletes work block 1 paid for.** Block 1 re-paths both checks because
it must be green alone; block 2 deletes `dependsOn("checkNoLongDashes")`, `dependsOn(
"checkEvidenceGuard")` and both task registrations from `build.gradle.kts`. The rework is the price
of blocks that stand alone, and it is one line each.

**The cold cache is accepted.** Dagger keeps its state in a Docker volume that dies with an
ephemeral runner, so `gradle/actions/setup-gradle` and the `type=gha` buildx cache both go and every
pull request pays a full build. The exits are named in ADR 0024's consequences and none is taken
today.

### 4.5 Continuous integration after Dagger

`validate.yml` stops enumerating checks. It keeps the jobs whose value is their identity in the
GitHub interface, and each becomes one call:

| Job | Becomes |
|---|---|
| `lint`, `test` | One job calling `dagger call gate`. Both `needs` arrays follow the rename |
| `build-image` | `dagger call image` then `dagger call smoke`, then the release steps unchanged |
| The release steps | Untouched YAML: GHCR login, metadata, push, cosign keyless attestations, both SBOMs, the OpenVEX predicate |
| `gate` (the required check) | Its mechanism and its check name are unchanged, which is what branch protection depends on. Its `needs` list follows the job rename |

Reading which check failed moves from a job name to the Dagger trace, one span per function, the
same trace locally and in continuous integration. `fetch-depth: 0` becomes necessary for block 4.

**This widens what a pull request must satisfy.** Section 2, property 4: the type resolution rules
run on no pull request today, and a single call to the gate runs them. Block 2 may therefore surface
findings the local gate has been absorbing alone, and its pull request states them.

### 4.6 The hooks (block 2)

`pre-commit` keeps its first half, the em dash and en dash refusal on staged additions, and loses
its `exec ./scripts/generate-openapi.sh`. The contract's synchronisation becomes a gate
verification that names the command to run. A hook that rewrites the working tree mid-commit and
asks for the commit to be repeated is a documented pitfall in `AGENTS.md`; this deletes the pitfall
with its cause, and `agents/writing.md`'s description of the generated regime follows.

`pre-push` calls `dagger call gate`. It already calls `gate` today, so its coverage does not change;
what changes is that its coverage becomes the same object continuous integration runs.

### 4.7 The breaking change guard (block 4)

`oasdiff` runs inside the Dagger gate, per ADR 0024 decision 5. Two checks, each with its own
observable.

1. **No break against a still served major.** Compares `contract/openapi.json` against each document
   in `contract/frozen/`. The directory is empty during the alpha, so a wrong path, a wrong flag or
   a swapped base and revision would all be green. The criterion therefore does not depend on the
   alpha: during Verify, block 4 drops a throwaway document into `contract/frozen/`, breaks the
   contract against it, shows the red, then removes both.
2. **The declared version matches the diff.** Derives the required bump from the diff against the
   contract on `main` and fails when `info.version` does not carry it. Break the contract on
   purpose, show the red, revert, show the green.

The second needs git history inside the container. The failure mode it exists for is silent: a
break released under a minor bump, accepted by a client of the previous major, failing later at a
user's. The other direction, a feature added without a minor bump, is merely annoying and visible.

### 4.8 What `clients/` will be, and what this lot does not build

`clients/` is not created by this lot. It is described here so the blocks above can be judged
against their consumer, as `docs/adr/0018-a-block-is-a-pull-request.md` requires when a surface's
real consumer arrives later.

- `clients/packages/api-client`: generated at install time from `contract/openapi.json`, never
  committed. It performs the handshake once and exposes its result.
- `clients/packages/auth`: the token, its storage and its renewal, shared because both clients are
  cross origin and token based.
- `clients/apps/webapp`: a static bundle, its own image, its own version.
- `clients/apps/extension`: its own store cycle, and the only client that forces backwards
  compatibility on the API.
- The coverage bound covers the logic these applications separate from their views. A boundary rule
  enforces the separation. Neither is configured by this lot.

## 8. What is not validated

- **That a Dagger function can run this repository's gate unchanged inside a container.** This is
  the claim the lot rests on: the JDK 25 toolchain provisioning from inside the container, native
  libvips, `python3` for the evidence guard, the Quarkus augmentation, Ebean's bytecode
  enhancement, sqlite-jdbc's native access, and the two tests that read `../Dockerfile` from the
  test JVM's working directory. If it is false, ADR 0024 decision 5 falls and blocks 2, 3 and 4 fall
  with it. **Block 1 survives it**, being a pure move, and that separability is the lot's best
  property. Block 2 opens with the spike that settles it, before any workflow file is touched.
- **No measurement of what a Dagger gate costs on this repository.** The full build and test time on
  a cold cache is estimated, never measured. Block 2 measures it and this document is corrected in
  the `(Corrected: ...)` form if the number changes the decision.
- **The multi architecture image build under Dagger** is documented as supported and has not been
  run here. Block 3 proves it, and its fallback is to leave `build-image` in YAML and keep only
  `smoke` in Dagger, which still buys the local smoke test.
- **The behaviour of the smoke test inside Dagger**, which needs a container started and polled from
  within the pipeline.
- **Whether `oasdiff`'s version checks parse a prerelease `info.version`.** Today's value is
  `1.0.0-SNAPSHOT`. Settled by running `oasdiff` over the current contract against a copy with one
  field removed, keeping the `-SNAPSHOT` suffix. Block 4 does that before writing anything.
- **That `oasdiff`'s inline annotations come with the action rather than the binary.** Asserted in
  section 7 and in ADR 0024's consequences; settled by reading the action's definition.
